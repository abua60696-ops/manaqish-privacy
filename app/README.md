# مناقيش دير الزور — تطبيق الزبائن (PWA)

تطبيق ويب تقدّمي (Progressive Web App) لمطعم مناقيش وبيتزا وفطائر في مدينة دير الزور، سوريا.
مبني بـ **React + Vite + TypeScript + Tailwind CSS + Firebase**، بواجهة عربية كاملة واتجاه RTL،
قابل للتثبيت على شاشة الهاتف الرئيسية، ويعمل جزئياً دون إنترنت (يمكن تصفّح القائمة حتى بدون اتصال).

هذا الدليل يشرح خطوة بخطوة كيفية إعداد المشروع وتشغيله ونشره، حتى لو لم يسبق لك التعامل مع Firebase.

---

## 1. نظرة عامة على البنية

```
app/
├── src/
│   ├── components/     مكوّنات مشتركة (الهيدر، بطاقة الصنف، شريط السلة...)
│   ├── pages/           صفحات التبويبات الأربعة + السلة/الدفع/التتبع
│   ├── context/         حالة عامة: المصادقة، السلة، الوضع الليلي
│   ├── hooks/           useOpenHours, useOnlineStatus
│   ├── services/        كل التواصل مع Firebase (auth, firestore, whatsapp)
│   ├── data/            menu.ts, exchangeRates.ts, districts.ts — عدّل القيم من هنا
│   └── types/           أنواع TypeScript المشتركة
├── public/               الأيقونات والصور المؤقتة (Placeholder) وملف manifest
├── firestore.rules       قواعد أمان قاعدة البيانات
├── firebase.json         إعداد النشر على Firebase Hosting
└── .env.example          نموذج مفاتيح Firebase
```

## 2. إنشاء مشروع Firebase

1. اذهب إلى [Firebase Console](https://console.firebase.google.com) وسجّل الدخول بحساب Google.
2. اضغط **"إضافة مشروع" (Add project)**، واختر اسماً (مثلاً `manaqish-deir-ezzor`).
3. يمكنك تعطيل Google Analytics إن لم تكن بحاجته (اختياري).
4. بعد إنشاء المشروع، من الصفحة الرئيسية اضغط على أيقونة **الويب `</>`** لإضافة تطبيق ويب.
5. سمِّ التطبيق (مثلاً "مناقيش - الزبائن") ثم اضغط **تسجيل التطبيق (Register app)**.
6. ستظهر لك قيم `firebaseConfig` — احتفظ بهذه الصفحة مفتوحة، ستحتاجها في الخطوة 5.

---

## 3. تفعيل Google Sign-In

1. من القائمة الجانبية في Firebase Console: **Build → Authentication**.
2. اضغط **البدء (Get started)**.
3. من تبويب **Sign-in method**، اختر **Google** من قائمة المزوّدين.
4. فعّله (Enable)، اختر بريد الدعم الظاهر للمستخدمين، ثم احفظ.
5. من تبويب **Settings → Authorized domains**: تأكد أن نطاق النشر (مثلاً `your-project.web.app` أو نطاق GitHub Pages) مضاف. أثناء التطوير المحلي `localhost` مضاف تلقائياً.

---

## 4. إنشاء قاعدة بيانات Firestore

1. من القائمة الجانبية: **Build → Firestore Database**.
2. اضغط **إنشاء قاعدة بيانات (Create database)**.
3. اختر موقع الخادم الأقرب (مثلاً `eur3` أو أي موقع أوروبي).
4. ابدأ في **وضع الإنتاج (Production mode)** — سنضع قواعد الأمان بأنفسنا في الخطوة التالية.

### نشر قواعد الأمان (firestore.rules)

يحتوي المشروع على ملف `firestore.rules` جاهز. لنشره:

- **عبر الواجهة:** افتح تبويب **Rules** داخل Firestore في الكونسول، الصق محتوى ملف `firestore.rules` بالكامل، ثم اضغط **نشر (Publish)**.
- **أو عبر سطر الأوامر** (إن ثبّتّ Firebase CLI، راجع القسم 8):
  ```bash
  firebase deploy --only firestore:rules
  ```

### المجموعات (Collections) التي يستخدمها التطبيق

لا تحتاج لإنشائها يدوياً — تُنشأ تلقائياً أول مرة يُكتب فيها مستند (مثلاً أول طلب يُرسله زبون). لكن للتشغيل الكامل من أول يوم يُفضّل تجهيز التالي يدوياً من تطبيق المدير أو مباشرة من الكونسول:

| المجموعة | الغرض | من ينشئها |
|---|---|---|
| `menu` | القائمة (اختياري — التطبيق يعمل بالقائمة المحلية في `src/data/menu.ts` إن لم توجد) | تطبيق المدير |
| `orders` | الطلبات الواردة | تطبيق الزبائن (هذا المشروع) |
| `users` | بيانات الزبائن المسجّلين | تطبيق الزبائن |
| `contests` | المسابقات | تطبيق المدير |
| `contestEntries` | مشاركات الزبائن في المسابقات | تطبيق الزبائن |
| `redemptions` | طلبات استبدال نقاط الولاء | تطبيق الزبائن |
| `settings` | مستند `loyalty` (قاعدة النقاط) ومستند `exchangeRates` (أسعار الصرف) | تطبيق المدير، أو يدوياً من الكونسول |
| `counters` | عدّاد رقم الطلب اليومي | تلقائي |

**لجعل مستخدماً "مديراً"**: افتح مجموعة `users` في الكونسول بعد أن يسجّل هذا الشخص دخوله مرة واحدة على الأقل، ثم أضف الحقل `role` بالقيمة `admin` على مستنده يدوياً.

**لتفعيل بطاقة النقاط بإعدادات مخصّصة**: أنشئ مستنداً باسم `loyalty` داخل مجموعة `settings` بالحقول:
```json
{
  "syrianPoundsPerPoint": 100,
  "rewards": [
    { "id": "free-drink", "label": "مشروب مجاني", "pointsCost": 50 },
    { "id": "free-pastry", "label": "فطيرة مجانية", "pointsCost": 100 },
    { "id": "free-medium-pizza", "label": "بيتزا وسط مجانية", "pointsCost": 200 }
  ]
}
```
إن لم يوجد هذا المستند، يستخدم التطبيق نفس القيم تلقائياً من ملف محلي.

**لتحديث أسعار الصرف دون إعادة نشر التطبيق**: أنشئ مستنداً باسم `exchangeRates` داخل مجموعة `settings`:
```json
{ "TRY": 43, "EUR": 1470, "USD": 1360, "SYP": 1 }
```
(كل رقم = كم ليرة سورية تساوي وحدة واحدة من تلك العملة)

## 5. ربط مفاتيح Firebase بالمشروع

1. انسخ ملف `.env.example` إلى ملف جديد باسم `.env` في مجلد `app/`:
   ```bash
   cp .env.example .env
   ```
2. افتح `.env` وضع فيه القيم التي حصلت عليها من صفحة `firebaseConfig` (الخطوة 2):
   ```
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_STORAGE_BUCKET=...
   VITE_FIREBASE_MESSAGING_SENDER_ID=...
   VITE_FIREBASE_APP_ID=...
   VITE_WHATSAPP_NUMBER=963947420675
   ```
3. **لا تشارك ملف `.env` مع أحد ولا ترفعه على GitHub** — هو مستثنى تلقائياً عبر `.gitignore`.

> إن نسيت إنشاء `.env` أو تركت حقلاً فارغاً، سيعرض التطبيق عند التشغيل شاشة توضح بالضبط أي متغيّر ناقص، بدل شاشة بيضاء غامضة.

## 6. تشغيل المشروع محلياً

يتطلب [Node.js](https://nodejs.org) نسخة 18 أو أحدث.

```bash
cd app
npm install
npm run dev
```

افتح الرابط الذي يظهر في الطرفية (عادة `http://localhost:5173`). أي تعديل في الكود ينعكس فوراً.

للتحقق من عدم وجود أخطاء TypeScript:
```bash
npm run lint
```

## 7. استبدال الصور المؤقتة بصورك الحقيقية

كل صور الأصناف حالياً هي رسومات SVG مؤقتة (Placeholder) في `public/images/`. لاستبدالها:

1. ضع صورك الحقيقية (jpg أو png أو webp) داخل `public/images/`.
2. افتح `src/data/menu.ts` وغيّر قيمة `image` لكل صنف إلى مسار صورتك، مثلاً:
   ```ts
   { id: 'pizza-pepperoni', ..., image: '/images/pizza-pepperoni.jpg' }
   ```
   كل صنف له مسار صورة مستقل، لذلك يمكنك تعديلها واحداً واحداً دون المساس بأي شيء آخر.

لتعديل الأسعار أو إضافة صنف جديد بالكامل، عدّل نفس الملف `src/data/menu.ts` فقط — هو المصدر الوحيد لكل الأصناف والأسعار محلياً، والتطبيق يفضّل تلقائياً القائمة من مجموعة `menu` في Firestore إن وُجدت.

## 8. البناء والنشر

### أ) البناء (Build)

```bash
npm run build
```

يُنتج مجلد `dist/` يحتوي التطبيق جاهزاً للنشر على أي استضافة ملفات ثابتة.

### ب) النشر على Firebase Hosting (موصى به)

1. ثبّت أدوات Firebase عالمياً (مرة واحدة فقط):
   ```bash
   npm install -g firebase-tools
   ```
2. سجّل الدخول:
   ```bash
   firebase login
   ```
3. اربط مجلد `app/` بمشروعك: انسخ `.firebaserc.example` إلى `.firebaserc` وضع فيه معرّف مشروعك (Project ID الظاهر في إعدادات Firebase)، أو ببساطة نفّذ:
   ```bash
   firebase use --add
   ```
   واختر مشروعك من القائمة.
4. ابنِ وانشر:
   ```bash
   npm run build
   firebase deploy --only hosting
   ```
5. سيعطيك رابطاً مباشراً مثل `https://your-project.web.app` — هذا هو رابط تطبيقك الجاهز، ويمكن تثبيته من المتصفح على شاشة الهاتف الرئيسية مباشرة.

### ج) النشر على GitHub Pages (بديل)

1. ابنِ المشروع: `npm run build`.
2. ارفع محتوى مجلد `dist/` إلى فرع `gh-pages` (يدوياً، أو عبر إجراء GitHub Actions من اختيارك).
3. فعّل GitHub Pages من إعدادات المستودع، واختر الفرع `gh-pages`.
4. **مهم:** أضف رابط GitHub Pages إلى **Authorized domains** في Firebase Authentication (الخطوة 3) وإلا فشل تسجيل الدخول بجوجل.

> ملاحظة: إعداد `base: './'` في `vite.config.ts` يجعل مسارات الملفات نسبية، لذلك يعمل البناء بشكل صحيح سواء نُشر على الجذر أو داخل مجلد فرعي مثل GitHub Pages.

## 10. ملاحظات تقنية مهمة

- **التوجيه (Routing):** يستخدم التطبيق `HashRouter` (روابط بصيغة `#/menu`) عمداً، لأنه يعمل مباشرة على أي استضافة ثابتة (GitHub Pages، Firebase Hosting) دون أي إعداد خادم إضافي لإعادة التوجيه.
- **العمل دون إنترنت:** بفضل `vite-plugin-pwa`، تُخزَّن ملفات الواجهة (JS/CSS/الصور) تلقائياً بعد أول زيارة، وتُعرض القائمة المحلية في `src/data/menu.ts` فوراً إن تعذّر الوصول إلى Firestore خلال ثوانٍ قليلة، بدل بقاء الشاشة فارغة.
- **رقم الطلب اليومي:** يُولَّد تلقائياً بصيغة `#001`, `#002`... ويُعاد من جديد كل يوم، عبر مستند عدّاد في مجموعة `counters` (لا يحتوي بيانات شخصية).
- **تتبّع الطلب المباشر:** متاح فقط للزبائن المسجّلين بحساب Google (تماشياً مع قواعد الأمان)، أما الضيف فيحصل على شاشة تأكيد برقم الطلب فقط.
- **دور المدير:** يُمنح يدوياً بإضافة `role: "admin"` على مستند المستخدم في `users` — راجع القسم 4.
